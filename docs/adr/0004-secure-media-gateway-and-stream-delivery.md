# ADR 0004: Secure Media Gateway and Stream Delivery

- Status: Accepted
- Decision date: 2026-09-16

## Context

Phase 2 established bounded HULK sessions, server-held Provider credential leases, and an SSRF-safe validated-IP Provider connection boundary. Phase 3 established normalized Live, Movie/VOD, and Series catalog identifiers without exposing Provider media URLs. Phase 4 needs to turn those authenticated catalog identities into playable media while preserving the rule that permanent Provider credentials and reusable credential-bearing Provider URLs remain server-side.

HLS introduces secondary Provider/CDN destinations through manifests. VOD and episodes need browser byte-range behavior without buffering whole files. Some containers can be made browser-usable by stream-copy remux when codecs are already compatible, but container extension alone is not sufficient evidence that remux is safe. Long-lived media responses must also stop within a bounded interval after the owning HULK session is revoked or expires.

## Decision

1. Media authorization is a HULK-owned capability layered on the existing session boundary. A media locator is AES-256-GCM encrypted with a distinct HKDF-derived media-locator key. Its encrypted payload is bound to a SHA-256 representation of the owning HULK session, has a five-minute maximum lifetime clipped to the session expiry, and contains either a server-authorized logical media identity or a nested HLS target. Provider credentials and Provider/CDN URLs never appear in locator plaintext.
2. Locator issuance requires an active HULK session and validates media against the Phase 3 catalog surface. Live IDs must be present in the current Live catalog, Movie IDs are resolved through Movie details, and episode IDs must belong to the requested normalized Series details. The browser cannot submit an arbitrary upstream URL, hostname, Provider path, or request header.
3. Live playback uses an HLS gateway. Root and nested manifests are bounded to 2 MiB and parsed as UTF-8 HLS text. Relative references resolve against the current upstream manifest URL. URI lines and URI-bearing `EXT-X-KEY`, `EXT-X-MAP`, `EXT-X-MEDIA`, `EXT-X-I-FRAME-STREAM-INF`, `EXT-X-SESSION-KEY`, applicable `EXT-X-SESSION-DATA`, `EXT-X-PART`, `EXT-X-PRELOAD-HINT`, and `EXT-X-RENDITION-REPORT` structures are rewritten to fresh HULK-owned locators. Unknown URI-bearing tags and unsupported URI schemes fail closed. Rewritten manifest text is rejected if any plaintext upstream HTTP(S) URI remains. Credential safety follows field ownership: Provider credentials can occur only inside server-owned upstream URI construction or parsed upstream URI fields, all of which remain server-side or are replaced by opaque HULK locators; ciphertext and unrelated scalar text are not rejected because of coincidental substring equality.
4. Every nested HLS/CDN HTTP(S) destination is re-approved through the same public-destination SSRF rules used for Provider traffic. DNS candidates are validated as a complete set, the actual connection is pinned to an approved address/family, original Host and HTTPS SNI/certificate identity are preserved, TLS verification remains enabled, and redirects are rejected rather than followed.
5. Binary HLS resources and VOD/episode bytes are streamed with Node stream backpressure. The media transport has bounded connection, response-header, and idle-read timers, an eight-hour hard stream-duration ceiling, and a 64 GiB hard byte ceiling. Downstream disconnect aborts upstream work.
6. MP4 VOD/episode delivery supports one browser byte range at a time. Closed, open-ended, and suffix `bytes=` ranges are accepted and normalized. Multiple or malformed ranges fail with `416`. Valid upstream `200`, `206`, `Content-Range`, `Accept-Ranges`, and trustworthy numeric `Content-Length` values are handled without buffering the complete object. A `206` without a valid `Content-Range` fails closed. Provider `Set-Cookie`, `Location`, and arbitrary response headers are never forwarded.
7. Non-MP4 VOD/episode containers enter the adaptation path only after bounded probe evidence. FFprobe and FFmpeg are invoked through `spawn` with `shell: false`, a minimal `PATH`-only environment, `pipe:0` input, protocol whitelist restricted to `pipe`, bounded execution, cancellation, and bounded process concurrency/queueing. Neither child process receives a Provider URL, Provider credential, session token, or inherited secret environment. Raw stderr is discarded from the browser boundary.
8. Stream-copy remux is permitted only when the probe proves exactly one H.264 video stream and one or more AAC audio streams. FFmpeg maps the first video/audio streams and emits fragmented MP4 using `-c copy`. Unknown, incompatible, or unproven codecs return an adaptation-required result. Phase 4 does not automatically transcode.
9. A media response revalidates ownership of the existing HULK session every 15 seconds and has an independent timer for the known session expiry. Revocation, expiry, session-store failure during revalidation, downstream disconnect, or process cancellation aborts long-lived upstream/remux work. New requests always re-acquire the existing Provider credential lease first. A session-store failure while initially authorizing media is reported as HULK-owned service unavailability rather than being misclassified as session expiry.
10. External `ffprobe` and `ffmpeg` binary presence is a hosting/runtime qualification requirement. Source support does not prove those binaries exist in a deployment. No new npm media dependency is introduced.

## Consequences

- The browser sees only HULK media paths and short-lived opaque locators; reusable Provider credential-bearing media URLs remain server-side.
- HLS manifests can safely traverse Provider/CDN hosts without creating a browser-controlled generic proxy. Each nested destination remains subject to the production SSRF boundary.
- VOD seeking depends on the real Provider honoring useful Range semantics. The gateway handles valid `200`/`206`/`416` behavior but Phase 4 source tests do not substitute for real Provider Range qualification.
- Stream-copy remux is intentionally narrow. Media that cannot be positively proven as H.264 + AAC is not silently transcoded or guessed compatible.
- The 15-second session revalidation interval is the maximum intended authorization-retention bound for a healthy long-lived stream after server-side revocation, excluding network/process scheduling latency.
- Real Provider media behavior, Provider anti-hotlink requirements, FFmpeg/ffprobe installation, browser codec behavior, and device-specific playback remain separate runtime qualification work.
